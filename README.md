## 1. 课程要求原文与对照

| 课程要求 | 本计划对应 |
|---|---|
| 题目：自行选择 Kaggle 比赛题，或机器学习与自己研究方向结合的题目 | 第 13 节待确认；两种路径均适用本计划 |
| 答辩：最后 8 个课时，各小组（2~4 人）选一位代表用 PPT 介绍：背景、模型、实验结果与分析、总结 | P2 主讲；PPT 12 页，每页标负责人（第 9 节） |
| 每人根据自己负责的内容完成一份课程报告，工作量饱满，答辩同时提交双面打印纸质版 | 每人独立报告 12~18 页，章节不重叠（第 9 节）；打印清单见第 12 节 |
| 答辩时小组成员必须在场，根据各人负责内容回答问题，缺席成绩为 0 | 答题责任矩阵 + 每人 5 题答题卡（第 10 节） |
| 各小组需有 Python 编程能力 | 角色分配按 Python 熟练度优先（第 3 节） |

## 2. 项目目标与验收标准

### 2.1 三个交付物

| 交付物 | 数量 | 验收标准 |
|---|---|---|
| 答辩 PPT | 1 份 | 12 页内，10 分钟讲完，含背景/模型/结果/分析/总结 |
| 课程报告 | 3 份（每人 1 份） | 各 12~18 页，只写本人负责部分，双面打印装订 |
| 代码仓库 | 1 个 | 新人按 README 能一键复现全流程 |

### 2.2 项目级验收（M1/M2/M3）

- **M1（第 1 周末）**：三人独立跑出的 baseline 分数完全一致（误差 < 1e-6）。
- **M2（第 2 周末）**：每人手里有 1 组自做对照实验 + 1 张自画图 + 1 条量化结论。
- **M3（第 3 周末）**：三份报告初稿齐 + PPT 初稿 + 能脱稿回答 5 个预设问题。

## 8. 工程规范

### 8.1 仓库结构

```
ml-course/
├── README.md                 # 复现说明（P3 维护）
├── requirements.txt
├── Makefile                  # make data / train / eval / all
├── data/
│   ├── raw/                  # 只读，不进 git
│   ├── interim/
│   └── processed/            # 可重建
├── splits/fold_v1.json       # 冻结划分，全员唯一来源
├── src/
│   ├── data/                 # P1
│   ├── features/             # P1
│   ├── models/               # P2
│   ├── eval/                 # P3
│   └── common/               # 共用
├── configs/{base.yaml, exp_*.yaml}
├── reports/{exp_log.csv, figures/, P1/, P2/, P3/}
├── submissions/
└── ppt/
```

### 8.2 写权限划分（防互相覆盖）

| 目录 | 唯一修改人 |
|---|---|
| `data/`、`src/data/`、`src/features/`、`splits/` | P1 |
| `src/models/`、`configs/exp_p2_*` | P2 |
| `src/eval/`、`reports/figures/`、`README.md` | P3 |
| `src/common/` | 改动需三人中两人 review |

### 8.3 实验登记表 `reports/exp_log.csv`

```csv
run_id,date,owner,stage,model,feat_ver,split_ver,params_hash,cv_mean,cv_std,public_lb,git_commit,notes
```

- `stage` 取值：`data | feat | model | eval`
- 命名规范：`{owner}_{stage}_{model}_{featver}_{MMDD}`
- 示例：`p2_model_lgbm_f2_1103`

**铁律**：报告里出现的每个数字，都必须能按 `run_id` 查到、按 `git_commit` 复现。

### 8.4 协作约定

- `main` 分支保护，功能走 feature branch + PR，至少 1 人 review。
- 数据文件不进 git，用 checksum 校验。
- 固定随机种子；任何"结果变好"必须先排除 seed 波动。
- 每周一次周会，只过里程碑与阻塞项。

## 9. 报告与 PPT 分工

### 9.1 报告统一模板（每人 12~18 页，正文 ≥6000 字，以老师要求为准）

1. 摘要
2. 引言与问题定义
3. 相关工作
4. **方法与个人工作（4~6 页，差异最大的部分）**
5. 实验设置
6. **实验结果与分析（4~6 页，只放本人负责部分）**
7. 结论与局限
8. 参考文献
9. 附录：个人贡献声明 + 复现说明

### 9.2 章节归属（不重叠）

| 成员 | 核心章节 | 必备图表 |
|---|---|---|
| P1 | 数据描述、EDA、划分策略合理性、特征设计与消融 | 标签分布、缺失率、特征重要性、消融表 |
| P2 | 模型原理与结构、损失与正则、调参策略、模型对比、集成 | 结构示意图、学习曲线、模型对比表、超参敏感性 |
| P3 | 评估协议设计、稳定性、误差分析、可解释性、工程复现 | 混淆矩阵 / 残差图、badcase 示例、SHAP 图、seed 方差图 |

**防雷同三条**：

1. 背景与数据章节各自重写措辞；
2. 共用数字必须口径一致；
3. 每份报告首页写明"本人负责部分"。

### 9.3 PPT 结构（12 页，P2 主讲）

| # | 页面 | 负责人 |

## 11. 风险预案

| 风险 | 触发信号 | 预案 |
|---|---|---|
| 模型涨不上去 | M2 时最好成绩 ≈ baseline | 转"复现 + 分析"型结论：重点写消融、误差分析、失败原因 |
| 某人掉链子 | 连续 2 天无 run 记录 | 组长 24h 内重分配，拆成可独立完成的子任务 |
| 数据泄漏 | 线下 CV 远高于 public LB | 回 `fold_v1.json` 复核分组 / 时序，不要硬解释 |
| 时间不够 | 距答辩 < 5 天且集成未做 | 按第 11.1 节砍任务 |
| 打印出问题 | 答辩前 1 天 | 提前 2 天打印，PDF 双备份，页码连续 |
