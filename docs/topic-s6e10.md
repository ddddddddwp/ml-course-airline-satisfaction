### 2.1 三个必须写进报告的领域事实

1. **0 分 = "不适用"，不是"最差"**。WiFi 评 0 的满意率 89%，评 1 只有 39%——U 型非单调。
   → 任何"评分求和/求均值"若不先处理 0，都会被污染。
2. **信号以阈值型为主**，跳变点多在 3→4（座椅/娱乐/餐食），2→3（值机/清洁）。
3. **主导特征是 Class=Business（满意率 72.5%）与 Online boarding**；延误信号很弱（无延误 45% → 延误>15min 31%）。

## 3. 增益预算（本文件最重要的一张表）

同一套 5 折、同一个 LightGBM，公开分析实测：

| 特征 / 环节 | OOF AUC | Δ | 归谁 |
|---|---:|---:|---|
| base：raw 21 特征 + 原生类别 | 0.95883 | — | P2 |
| + 朴素聚合组（n_zeros / 评分均值·最小值 / Travel×Class / arr−dep） | 0.95869 | **−0.0001** | P1 |
| + 同上但评分当类别处理 | 0.95868 | −0.0002 | P1 |
| + Age / Flight Distance 频次编码 | 0.95952 | +0.0007 | P1 |
| **+ counts + Flight Distance 折内目标编码** | **0.96022** | **+0.0014** | P1 |
| + 调参（lr 0.02 等） | 0.96025 | ≈0 | P2 |
| Public LB 第 1 名 | 0.96416 | +0.0053 | — |

**读法（必须让 P2/P3 都理解）**：

- 这个数据集 **95% 的信号已经在 raw 特征里**。树模型不需要你帮它聚合。
- P1 全部特征工程的增量是 **+0.0014**；而"看起来最有道理"的聚合组是 **负增益**。
- 想从 0.960 走到 0.964，靠的是**多模型族集成**（+0.002~0.004），不是特征。
- 折间 std ≈ **0.0006**，比全部特征增益（0.0014）还大。
  → **不上 3 seeds × 5 folds，任何"提升"结论都站不住**。

## 4. 特征分组（重写：原 A/B/C 在此数据上不成立）

原方案"按航段/舱位分组统计聚合"**无法执行**——数据里没有航段/机场列，只有 `Flight Distance`。

| 组 | 内容 | 预期 | 备注 |
|---|---|---|---|
| **A 语义修正**（P1-06/07） | 14 个评分列：`is_zero` 标记 + 0→NaN + 只对 1–5 求统计量；延误 `log1p` + `is_delayed` + 缺失标记 | **必要**，不是加分项 | 不做这一步，后面全错 |
| **B 聚合/交互**（P1-08/09） | 评分 mean/min/std/五分数、`n_zeros`、Travel×Class 交叉、`arr−dep`、距离分箱 | **对树模型 ≈0 或负**；**对 LR 可能有正** | 价值在"异质性结论"，不在分数 |
| **C 频次编码**（P1-10） | `Flight Distance` / `Age` 频次编码（只用特征，全量统计安全） | 公开分析 +0.0007 | 无泄漏风险 |
| **T 目标编码**（P1-10） | `Flight Distance` 目标编码，**只在训练折 fit** | 公开分析再 +0.0007，合计 +0.0014 | 全项目唯一有泄漏风险的变换，单独成组、单独消融 |
| **D 可用性筛选**（新增） | 剔除 `Arrival Delay`（飞行后才可知）后重跑 | **实测 −0.00003（几乎无损失）** | 与起飞延误高度共线（r≈0.84），冗余而非必要 |

**消融表改为 5 组 × 2 模型族**：base / +A / +B / +C / all，分别在 LGBM 与 逻辑回归 上跑。
C 与 T 分开报（频次编码无泄漏风险，目标编码有），这样"折内拟合做对了"才可证。
理由：只有跨模型族对比，才能得出"聚合特征对线性模型有效、对树模型无效"这个**真结论**。
